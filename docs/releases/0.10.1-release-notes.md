# AssegaiPHP Core 0.10.1

Core 0.10.1 decouples application bootstrap from queue backend availability.

## What changed

- adds an injectable `QueueFactory` for resolving configured `driver.connection` queue names programmatically
- keeps one queue instance per named connection for the lifetime of the application graph
- resolves `#[InjectQueue]` through the container's parameter-resolver seam instead of performing work inside the attribute constructor
- keeps queue attributes as metadata and delegates driver validation and creation to the named factory
- retains the application queue factory across request-scope refreshes in reusable runtimes
- documents that queue drivers must defer broker I/O until an operation needs the transport

## Compatibility

- requires `assegaiphp/common:^0.10.0`
- lazy broker availability requires `assegaiphp/rabbitmq:^1.1.2` or `assegaiphp/beanstalkd:^1.1.2`
- existing `#[InjectQueue('driver.connection')] QueueInterface` constructor injection remains source compatible

## Upgrade notes

Applications can continue using `#[InjectQueue]` without changes. Code that manually reads `queues.php` and calls a driver's static `create()` method can instead inject `QueueFactory` and call `connection()`.

Queue connection failures now occur at the first broker-backed operation rather than while the application graph is constructed. Handle enqueue failures at the domain boundary where the application can decide whether to return an error, persist an outbox record, or apply another explicit fallback.
